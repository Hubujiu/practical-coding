# Evolution wiki

This is the persistent maintenance knowledge layer between raw experience and runtime Skill wording.

Create one page per reusable mechanism, not per benchmark case. A good page answers:

- what repeated mechanism was observed;
- which independent receipts support or contradict it;
- which execution/retrieval boundary or capability node it concerns;
- what routing signal is observable before action;
- what candidate change could exploit that signal;
- what evidence would falsify the candidate change.

Suggested page shape:

```markdown
# Mechanism: <name>

## Claim
## Observable trigger
## Supporting receipts
## Contradicting receipts
## Affected nodes/boundaries
## Candidate experiments
## Current status
```

Do not store raw traces here. Link to benchmark artifacts or experience receipts. Do not promote a page directly into runtime text; freeze an experiment first.
