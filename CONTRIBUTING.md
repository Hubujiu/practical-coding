# Contributing

Contributions should preserve the project's compact decision-making role.

- Keep `SKILL.md` limited to `Boundaries` and `Decision Flow`.
- Write every boundary as one complete sentence.
- Keep the workflow as one decision flow without examples or commentary.
- Keep conditional operational detail in focused references instead of adding more top-level Skill sections.
- Avoid adding scripts, dependencies, modes, or configuration unless they are necessary.
- Preserve the user-confirmation loop before executing a created or restored execution document.
- Explain any change to the solution priority, testing and verification stance, debugging policy, Git requirement, execution document, or Mock.js rule.

Open an issue before proposing a change that alters the project's core philosophy.
